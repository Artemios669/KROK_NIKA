# НИКЕР — MVP подбора питомца

Демонстрационное веб-приложение для бережного подбора животного: диалог, свайпы по анонимным характеристикам (до 10 карточек), детерминированный алгоритм совпадений, профиль животного, заявка и демо-панель.

## Запуск

Нужны Node.js 20+ и pnpm. В папке проекта выполните:

```bash
pnpm install
pnpm dev
```

Откройте `http://localhost:3000`. Проверка алгоритма: `pnpm test`. Сборка: `pnpm build`.

## Режимы

Без действующего ключа приложение работает в демонстрационном режиме; карточки и ответы чата — тестовые.

## Подбор животных

Подбор рассчитывается на сервере через `/api/recommendations`. Профиль проверяется по Zod-схеме, а сравнение выполняется по пяти группам ТЗ: активность и образ жизни (30%), характер (25%), условия содержания (20%), семья и другие животные (15%), возраст и дополнительные предпочтения (10%). Животные другого выбранного типа и недоступные для пристройства исключаются. Известные несовместимости с детьми, другими питомцами, временем одиночества, явно обязательными условиями жилья и специальным уходом фильтруются до ранжирования. Неизвестные поля не считаются совпадениями и уменьшают полноту доступных данных.

Свайпы по характеристикам могут немного менять порядок животных, но не меняют отображаемый процент и не обходят обязательные фильтры. Рядом с верхней рекомендацией показывается детерминированное объяснение по совпавшим факторам и полноте данных; неизвестные поля не заполняются догадками. Объяснение работает без ИИ и не расходует квоту Gemini. Если данных для оценки нет, вместо фиктивного процента показывается, что информации недостаточно.

## Gemini API (бесплатная квота)

Чат уже подключён к Gemini через серверный маршрут `/api/chat`. Для запуска с ИИ:

1. Откройте [Google AI Studio](https://aistudio.google.com/app/apikey), войдите в Google и создайте API key.
2. В корне проекта скопируйте `.env.example` в `.env.local`, если такого файла ещё нет.
3. В `.env.local` укажите ключ и модель:

   ```dotenv
   GEMINI_API_KEY=вставьте_сюда_свой_ключ
   GEMINI_MODEL=gemini-3.5-flash-lite
   ```

4. Сохраните файл, перезапустите `pnpm dev` и откройте `http://localhost:3000/chat`. Убедитесь, что в чате отображается «GEMINI-ПОМОЩНИК».

Ключ используется только на сервере и не должен попадать в браузер, Git или сообщения. Не отправляйте его другим людям. Если ключ уже задан, но запрос не работает, создайте новый в AI Studio и замените значение в `.env.local`; после изменения перезапустите сервер. Бесплатная квота ограничена и зависит от доступности модели, региона и условий Google. При исчерпании квоты подождите её восстановления; не подключайте платный биллинг, если не хотите расходов. Без ключа приложение остаётся доступно в демонстрационном режиме. Переменные `OPENAI_API_KEY` и `OPENAI_MODEL` для текущего чата не нужны.

Чат собирает несколько связанных сведений за один ответ: например, жильё и состав семьи, тип питомца и предыдущий опыт, распорядок и прогулки. Каждый ответ разбирается на факты по всем темам; профиль дополняется, а Gemini получает его уже обновлённым. Следующий вопрос выбирается по оставшимся незаполненным полям, поэтому известные данные не спрашиваются заново. После подтверждения опыта ухода чат отдельно уточняет, как человек действовал при серьёзной болезни питомца. Неизвестную тему можно пропустить — она останется неизвестной и не будет считаться совпадением при подборе. Кнопка перехода к свайпам появляется после пяти ответов на обязательные вопросы; пользователь может остаться в чате и продолжить разговор. Если запрос к настроенному Gemini временно не проходит, приложение покажет ошибку и кнопку повтора, не теряя отправленный ответ.

## Supabase: подключение и работа с данными

Без Supabase приложение показывает тестовые карточки и демо-ответы чата. В этом режиме вопросы и заявки не сохраняются. Чтобы отправлять их и видеть в админ-панели, подключите базу:

1. Создайте проект на [supabase.com](https://supabase.com/).
2. В панели проекта откройте **SQL Editor → New query**. По очереди откройте и выполните:
   - `supabase/migrations/001_initial.sql`
   - `supabase/migrations/002_animal_characteristics.sql`
   - `supabase/migrations/003_storage_rls.sql`
   - `supabase/migrations/004_staff_workflow.sql`
   - `supabase/migrations/005_imported_catalog_ids.sql`
   - `supabase/seed.sql` — только если вы используете стандартную таблицу `animals` и хотите добавить 20 тестовых карточек. Не запускайте seed для каталога `animalsss`.

   Если миграции `001`–`004` уже запускались, повторно их не выполняйте — примените только `005_imported_catalog_ids.sql`.
3. В **Project Settings → API** скопируйте **Project URL** и публичный **anon / publishable key**. В корне проекта создайте `.env.local` и заполните:

   ```dotenv
   NEXT_PUBLIC_SUPABASE_URL=https://ваш-проект.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=ваш-публичный-ключ
   SUPABASE_ANIMALS_TABLE=animalsss
   ```

4. Для чтения данных в админ-панели скопируйте секретный ключ проекта (**service_role** или серверный **secret key**) в `SUPABASE_SERVICE_ROLE_KEY`. Он используется только сервером. Никогда не называйте его `NEXT_PUBLIC_*`, не отправляйте в чат и не добавляйте в Git. Публичные формы работают через anon key и ограничиваются RLS-политиками.
5. Задайте собственный длинный пароль админ-панели:

   ```dotenv
   ADMIN_PASSWORD=ваш-длинный-уникальный-пароль
   ```

6. Проверьте RLS-политику `SELECT` для `animalsss`: anon key должен видеть только карточки, которые разрешено показывать посетителям. Политики из миграций проекта автоматически применяются к `animals`, но не к вашей отдельной таблице `animalsss`. Перезапустите `pnpm dev`. Откройте `/api/animals`: поле `source` должно быть `"supabase"`, а `totalRecords` — показывать число записей, доступных приложению с учётом RLS. В текущем каталоге `animalsss` отсутствие статуса доступности считается допустимым для подбора, поскольку пользователь подтвердил, что каталог содержит животных для пристройства; явный отрицательный статус по-прежнему исключает запись. При всех 428 видимых строках ожидайте `totalRecords: 428`; `eligibleRecords` показывает число животных с распознанным типом и подходящим статусом. `unavailableRecords`, `unconfirmedAvailabilityRecords` и `unsupportedTypeRecords` помогают проверить качество исходных данных. Для таблицы `animalsss` приложение читает страницы по 500 строк и преобразует текстовые поля в типы подбора; неизвестные характеристики не превращаются в совпадения. Ошибка таблицы или схемы больше не переключает каталог молча на тестовые данные.

   Идентификаторы `animalsss.id` — текстовые, поэтому миграция `005_imported_catalog_ids.sql` добавляет поля `source_animal_id` и `source_animal_name` для вопросов и заявок, не меняя существующие UUID-связи таблицы `animals`. Проверить обращения можно через **Table Editor** в Supabase; вопросы и заявки также доступны на странице `/admin`.

В `/admin` можно ответить на ожидающий вопрос: после сохранения он помечается как отвеченный и появляется на странице соответствующего животного. Для заявки доступны статусы **Новая**, **В работе**, **Одобрена** и **Отказ**. Посетители видят только опубликованные ответы приюта, но не видят список заявок и контакты.

Если Supabase не настроен, приложение явно работает с демонстрационными данными. Если Supabase настроен, но чтение таблицы завершается ошибкой, приложение покажет ошибку, а не подменит каталог тестовыми записями. Пустая таблица вернёт пустой каталог. Для вопросов и заявок выберите карточку из каталога Supabase: текстовые ID из `animalsss` сохраняются отдельно от UUID стандартной таблицы `animals`. Ошибки подключения не считаются успешным сохранением.

Для Vercel добавьте те же переменные в **Project Settings → Environment Variables** для нужных окружений и выполните новый Deploy. `SUPABASE_SERVICE_ROLE_KEY` и `ADMIN_PASSWORD` должны быть только серверными переменными. Не копируйте реальные ключи в README, `.env.example` или клиентский код.

В демокаталоге и SQL seed содержится по 20 карточек с одинаковыми именами и характеристиками. Это вымышленные тестовые записи, а фотографии — иллюстрации из Unsplash, не фотографии именно этих животных. Даже загруженные из Supabase тестовые записи отмечаются в интерфейсе как демонстрационные; смешанный каталог отдельно сообщает о тестовых карточках. Перед production замените данные и изображения на проверенные материалы приюта. `null` у совместимости и пустые дополнительные поля означают «неизвестно / не подтверждено», а не «нет». Дополнительные карточки характеристик берут сведения из `coat_details`, `ear_shape`, `shelter_story`, `health_notes` и `interesting_facts`; пустые поля в свайпах не показываются.

## Vercel

Импортируйте репозиторий в Vercel, добавьте переменные окружения из `.env.example` в настройках проекта и выполните Deploy. Миграции Supabase применяются отдельно в SQL Editor или CI.

## Структура

`app/` — страницы и API, `lib/matching/` — алгоритм, `types/` — модели, `supabase/migrations/` — SQL, `tests/` — сценарии алгоритма. Код намеренно компактный и снабжён ясно выделенными demo-данными, чтобы его было удобно развивать начинающим разработчикам.
